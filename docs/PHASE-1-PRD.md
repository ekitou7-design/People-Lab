# Order2People 第一阶段需求

状态：规划草案，未实现，待审核。产品边界见 [PRODUCT](PRODUCT.md)，字段与接口见 [API-CONTRACTS](API-CONTRACTS.md)。

## 目标与流程

生产主管录入订单 → AI 提取草稿/人工选择工艺 → 主管确认数量、窗口、工序及标准版本 → 系统验证资格、日历和已有占用 → 引擎分配共享人员容量 → HR 查看缺口、依据和缺失项 → 确认后导出 SkillBridge 需求。

AI 不生成标准工时、资格事实或需求人数；每个提取值附原文出处，低置信度、冲突或缺失值提示人工确认。自然语言服务不可用时仍可人工录入走完整闭环。确认提取不等于确认计算结果。

## 优先级与范围

| 优先级 | 功能 | 交付边界 |
| --- | --- | --- |

| P0 | 验证、确定性分配、缺口明细和审计 | 单场地多订单联合计算；不含机器/物料约束 |

## 输入与确定性规则

计算输入须覆盖目标场地与窗口内全部在途订单、已承诺任务和可用人员；范围外供给不得默认加入。用户确认数据完整范围。资格目录缺失与人员资格不合格应分别处理。

- 订单：订单/产品标识、数量及单位、开始/截止时间、工艺版本、每工序数量和执行窗口。未提供工序窗口时阻断，不能平均分摊猜测。
- 标准：每单位人工秒数、批次准备人工秒数、批量、岗位、技能等级和资格要求、生效区间及来源。仅接受人工工作量，不把机器节拍直接当人工工时。
- 人员：激活状态、技能等级、资格有效区间、场地、逐日工作区间、休假及既有任务占用。空占用列表须明确确认“无任务”，未知不得当零。
- 第一阶段时间桶为场地本地自然日，Asia/Shanghai；区间采用 [start,end)，跨日分段；工序必须明确分配到每日的数量与批次。同一工序多项技能为同一执行者必须同时满足的资格组合；多人协作需拆成独立人工需求行并显式记录人数与工时依据，不能凭空复制工时。
- 每行需求秒数 D = 数量 × 单位人工秒数 + 批次数 × 准备人工秒数；批次数由明确批量向上取整或人工确认。均用整数秒；显示小时只做展示舍入。
- 人员可用秒数 A = 当日班次与窗口交集的并集长度 − 其中休假和既有任务占用并集长度。重叠占用不重复相减，越界占用只扣交集。已列入本次待分配订单的占用必须剔除重算，不能既扣占用又重复纳入需求。
- 资格需覆盖实际任务时段；第一阶段按完整日桶执行窗口验证。有效期中途失效且不能精确拆分时阻断。没有资格/过期/等级不足者不建立该需求的供给边；未核实资格不得认作合格。
- 每日构建人员→需求行的整数容量最大流：人员总分配 ≤ A，需求分配 ≤ D，只连接全部资格匹配的人员。人员跨技能共用同一容量，禁止各岗位分别求和。稳定排序按人员 ID、需求 ID；固定引擎版本和排序以保证重放一致。
- 缺口 = D − 已分配秒数，按需求行输出。可替代技能竞争造成的明细分配依赖约定排序，应展示分配策略与竞争关系；不将逐行缺口简单解释为独立招聘人数。
- 日桶内工时可切分是明确假设；工序先后、分钟级冲突、连续作业和设备瓶颈不在本模型保证范围。若业务要求这些约束，本次计算阻断并提示不支持，不能宣称可排产。
- 第一阶段最终输出以未覆盖人工秒数为准。仅在显式提供单人同期净容量及可互换资格组合时展示 ceil(缺口/净容量) 参考人力当量，并标注不能跨行相加、不能直接等同招聘人数；未提供时该字段为 null。

## 输出、状态与变更

输出：订单/工艺/人员快照版本、数据完整范围、引擎版本、逐行需求/分配/缺口、逐人分配、排除原因、来源、假设、缺失信息和需求 JSON。

草稿 → 已确认输入 → 验证 → blocked 或 calculated → HR confirmed → 导出。blocked 的缺口、最终总计和参考人数均为 null，允许展示已知需求与缺失项，但不得提供确定性总缺口或可执行下游需求。

订单时间、工艺、日历、占用、资格任一相关版本变化时旧结果标为 stale；历史保持不可变，可查看但不能确认或导出供执行。重新计算须使用新快照。计算不预订产能，两次分析不能当作两次独立可兑现承诺。

## 权限与异常

生产主管维护所属场地订单并确认工艺输入；数据维护者确认标准与资格；HR 发起计算、审阅并确认输出；员工不读取其他人员资格与分配。现有 manager 仅为演示主管，场地权限尚需新增，不能自动扩展全场权限。

标准缺失、单位不明、未知日历/占用、资格数据不完整、窗口非法、无适用工艺均阻断。明确无合格人员是可计算的缺口，不是数据缺失。输入负数/重复 ID/引用失效返回字段错误；版本并发冲突要求重新加载；服务异常保留草稿并允许安全重试。AI 输出必须经过相同服务端校验。不得用默认效率系数填补数据。

| 场景与输入 | 预期 |
| --- | --- |
| 100 件 × 360 人工秒，无准备工时；合格可用 8h | 需求 10h、分配 8h、缺口 2h；人数 null |
| 上例缺单位工时 | blocked，缺口 null，定位标准缺失 |
| 只有一位 8h 人员，资格不符合或已过期 | 需求 10h、分配 0、缺口 10h，显示排除原因 |
| 同一人两项资格、可用 8h；两项需求各 6h | 总分配 8h、总缺口 4h；不产生 16h 供给 |
| 多技能甲 8h，单技能乙 8h；A/B 需求各 8h，乙仅能 A | 分配乙到 A、甲到 B，总缺口 0，验证不能用简单逐行贪心 |
| 班次 8h，已有任务占 3h，休假与该任务重合 1h | 净可用 5h，不能扣成 4h；同源订单占用去重 |
| 日历或占用未知；资格档案未确认完整 | blocked，不能把未知视为零供给或全供给 |
| 订单移动到资格失效后或无班次的日期 | 旧结果 stale，新结果按新窗口重算 |
| 订单/资格/占用在确认前被队友更新 | 409 版本冲突；不能确认旧结果 |
| 120 件、批量 50、每批准备 600 秒 | 3 批；准备 1800 秒，附公式和来源 |
| 重复提交相同幂等键；相同键不同内容 | 返回相同记录；内容冲突返回 409 |
| HR 确认完整结果并导出 | schemaVersion、需求 ID、技能/资格、时段、缺口、来源完整；blocked/stale 禁止执行导出 |
| 禁止大模型杜撰；未授权员工请求结果 | 无依据字段保持待补充；越权拒绝且无人员资料泄露 |
