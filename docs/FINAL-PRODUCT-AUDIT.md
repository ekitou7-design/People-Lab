响应式实际抽样覆盖 1440px、1024px、390px：请假、培训、计算、人才证据、调配表单/拒绝、招聘关联、资格维护与过期历史。页级 `scrollWidth` 均等于视口宽；这不等于所有表格无需内部滚动。另用新 Chrome 以 390px 首次打开并独立复核导航及四项能力切换，排除了长截图中固定导航残片造成的误判。

## 3. 产品体验评价

招聘、入职、员工服务、培训已有较完整的工作台形态：人员上下文、原文证据、业务状态和下一步动作比较清楚；请假草稿可在知识引用往返后保留，实际任务与结果能回链。HR 审核、入职事实确认、主管风险确认均有业务用途，本轮没有为了缩短操作而删掉它们。

生产与 SkillBridge 的首次上手成本更高：初始化有先后顺序，页面仍展示 `inspect`、`pos-quality`、英文状态、版本与技术编号；高级资格维护需要结构化编辑，长风险说明与多层卡片增加阅读量。因此不能声称普通 HR 不看指南即可独立完成全部维护。本轮按指南完成全流程，没有做真人 HR 用户研究或把自动化速度当成人类熟练度。

整体更接近“已有稳定业务链的比赛演示产品”，原 HR 工作台完成度高于新模块的产品整合程度。仍有 AI 式解释性长文和工程术语；具体文案问题交由并行的文案任务，本轮没有全站改写、批量改名或变更应用提示文字。

## 8. 演示结果

在第三个全新隔离库，通过真实 Chrome 逐步 UI 操作计时：**约 17:48:23.454 → 17:51:01.840，2 分 38.383 秒**。耗时取计时记录的 `wallDurationMs`（单调计时）；显示的系统时钟首尾相减约为 2 分 38.386 秒。该耗时包含逐步核对、工具往返；不含真人口播，不是新手 HR 的学习时长。驱动动作累计约 3.826 秒也单独记录，不能把它当完整演示时间。没有用固定等待凑时长。

| 路线 | 本轮节点时间 |
| --- | ---: |
| 全新 HR 首页，0 订单、0 培训 | 0:00 |
| 内部人才样例 → 生产样例 → 核对范围 → 10/8/2 | 0:25 |
| HR 确认 → SkillBridge → 两名人才与三条路径 | 0:55 |
| 人工批准培养 → 执行 → 真实任务及来源 | 1:20 |
| 人工批准招聘 → 执行 → 草稿关联已有陈雨桐 | 1:58 |
| 刷新后重新找到招聘关联及培训任务 | 2:38 |

本轮路线全程不录入 JSON；所有审核和执行确认保留。3–5 分钟讲解可围绕上述主线安排，真人口播仍须演示者排练，不把本轮墙钟冒充真人讲稿实测。

复现按钮顺序（全新虚构库，顶部 HR 身份）：

1. SkillBridge → “载入内部人才演示样例”；生产需求 → “载入 / 重置演示样例”。
2. 核对每日 100 件、0 准备批次、360 秒标准和完整窗口；勾选完整性确认，点“确认输入并计算”，查看 10/8/2。
3. 点“HR 确认结果”→“前往 SkillBridge 分析”→“发起 SkillBridge 分析”，展开两名人才的资格与增量容量证据。
4. 内部培养方案点“HR 审核”，填审核说明并“批准”；再点“执行方案”→“确认执行”。
5. 点“查看已创建的培训任务”，核对虚构员工、任务和来源；点“查看原分析”返回。
6. 外部招聘方案同样人工批准并执行；点“前往招聘工作台查看需求草稿”，选择已有陈雨桐并“关联”。关联后状态进入招聘中，没有新增候选人。
7. 刷新页面，再进入招聘与岗位培训，核对同一草稿、候选人关联和真实任务仍在。边界与故障恢复见 [使用说明](USER-GUIDE.md)。

建议演示只突出一个价值链：**订单形成可复核的能力工时缺口；以同一需求快照比较人才路径；人工批准后任务/草稿真实写入并保留反馈。**正式资格变更与 10/10/0 作为可选加演，由演示者操作，不要求评委现场编辑结构化资料。

风险：必须先内部人才样例、后生产样例、再最终计算；样例写入会使旧结果过期。不要全局重置日常库；不要把原 8h 再补 2h，不要将培训通过说成正式资格；没有模型密钥也能演示，但必须如实说明固定规则和演示身份。
