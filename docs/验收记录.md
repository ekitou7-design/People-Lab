## 补充问答实测与修复

使用隔离数据库，对 12 组包含正常、非预设及越权请求的场景进行了实测，保留修复前的 test-results/assistant-audit.json，修复后的逐例输入、输出和业务状态见 test-results/assistant-audit-after.json。复测 12/12 通过，测试范围是规则分流及业务状态保护，并非真实大模型效果。

现在可执行 `npm run test:audit` 重放相同 12 组输入，不依赖已有报告文件。脚本在系统临时目录建立 SQLite 数据库，监听随机本地端口，输出 `test-results/assistant-audit-replay.json`，并验证余额、申请状态、培训状态、引用、跨轮补齐和人工工单去重。原两份历史报告保持原样；原始报告 SHA256 为 `e398bff4d8a906972b058ad706d1758a2a81ff69a557cea350218b650091a93d`。四个不支持的接口分别验证简历上传、新增候选人、模型列表和直接修改余额均返回 404。

- 已修复病假、婚假等非年假问题误出年假表单：现在明确演示仅支持年假并转交 HR。
- 已修复否定请假意图仍进入申请：例如“不想请假，想查培训”现在进入培训答复，单纯否定则澄清或转人工。
- 已修复“材料／资料”关键词误判入职：需要明确入职上下文。
- 余额加培训等复合咨询先请用户选择一项，不把单一规则答复当成完整理解。
- 问答请求直接修改余额、批准请假时，没有改变对应业务状态；员工审批接口仍拒绝该身份。此项只验证演示身份下的接口门禁，不代表已实现正式认证。
- 培训 API 测试另行验证未开始学习不能提交、失败后必须进入复练、重复提交保持幂等；这些属于 API 回归覆盖，未计入 12 组聊天审计。
- 服务加载修复后已重新启动；重启前后的候选人、员工、入职、请假、培训、咨询、消息和事件记录摘要哈希一致，用户现有业务记录完整保留。

## 验证边界

本版采用固定演示资料及明确规则模拟 AI。没有接入真实模型、任意简历上传、Frappe、Dify、飞书或其他外部业务系统。身份切换用于本地演示，不作为真实登录认证。培训结果仅表示本次模拟异常处置练习的结果。

安装依赖并完成构建后，运行演示不需要网络或模型密钥。源码、数据库与启停方式见 README.md；现场演示步骤见 docs/演示脚本.md。
