# HRFlow 本地 Demo 验收记录

验收日期：2026-10-30。运行环境：Windows、Node.js 25.8.1、React 19.3.1、Vite 8.3.5、Playwright 1.63.0、Chromium 153.0.8010.12。

## 已验证

- TypeScript 检查与生产构建通过。
- API 自动测试 14 项通过：招聘和入职状态、角色和个人记录隔离、知识引用和跨轮追问、工单及人工答复、请假校验与审批、幂等和余额保护、培训与唯一复练任务、SQLite 重启持久化、重置和错误返回，以及四类问答分流回归。
- 浏览器端到端验收 21 项通过。实际点击招聘、原文查看、录用、入职、身份切换、员工问答、申请预览、请假提交、主管审批、培训失败、复练再次失败、复练通过、驾驶舱及重置。发布副本重新安装依赖后复测通过，具体断言见 [浏览器测试报告](test-reports/e2e-report.json)。
- Yeeflow 参考风格的蓝白驾驶舱已目视核查，包含招聘漏斗、事务环图、岗位能力证据条、部门人数和规则协同助手。
- 在最终本地服务中另行验证协同助手可读取当前待审批摘要，并跳转到员工服务页面。
- 1024×768 平板驾驶舱与 390px 员工服务页面均无文档级横向溢出；浏览器未捕获未处理异常，完整流程没有外部网络请求。
- Windows PowerShell 5 实际启动成功；再次启动复用同一 PID；停止脚本成功关闭该 HRFlow 进程，验证前记录的其他 12 个长期 Node 进程均保持运行。
- Windows 中文目录下的 UTF-8 PID 文件读取已实际修复和回归验证。

浏览器测试使用系统临时目录中的独立数据库，并在测试结束后清理，不修改日常演示数据库。

## 补充问答实测与修复

使用隔离数据库，对 12 组包含正常、非预设及越权请求的场景进行了实测，保留 [修复前报告](test-reports/assistant-audit-before.json)，修复后的逐例输入、输出和业务状态见 [修复后报告](test-reports/assistant-audit-after.json)。复测 12/12 通过，测试范围是规则分流及业务状态保护，并非真实大模型效果。

- 已修复病假、婚假等非年假问题误出年假表单：现在明确演示仅支持年假并转交 HR。
- 已修复否定请假意图仍进入申请：例如“不想请假，想查培训”现在进入培训答复，单纯否定则澄清或转人工。
- 已修复“材料／资料”关键词误判入职：需要明确入职上下文。
- 余额加培训等复合咨询先请用户选择一项，不把单一规则答复当成完整理解。
- 请求直接修改余额、批准请假或绕过培训，并未改变对应业务状态；员工审批接口仍拒绝该身份。此项只验证演示身份下的接口门禁，不代表已实现正式认证。
- 服务加载修复后已重新启动；重启前后的候选人、员工、入职、请假、培训、咨询、消息和事件记录摘要哈希一致，用户现有业务记录完整保留。

## 验证边界

HR-V1 发布副本在 `People-Lab` 目录重新执行安装、构建、14 项接口测试和 21 项浏览器检查，全部通过。修复了健康接口测试写死原本地文件夹名称的问题，现在核对实际项目目录，克隆后可在不同目录名下运行。

本版采用固定演示资料及明确规则模拟 AI。没有接入真实模型、任意简历上传、Frappe、Dify、飞书或其他外部业务系统。身份切换用于本地演示，不作为真实登录认证。培训结果仅表示本次模拟异常处置练习的结果。

安装依赖并完成构建后，运行演示不需要网络或模型密钥。源码、数据库与启停方式见 README.md；现场演示步骤见 docs/演示脚本.md。
