# HRFlow AI · 协同工作台 v2

[打开可编辑 Figma Design 文件](https://www.figma.com/design/EBXWvieYKTM1od7pnZOrwS?node-id=6-1230)。文件使用当前连接团队的草稿，名称为“HRFlow AI · 协同工作台 v2”。

## 文件结构与使用

“01 基础组件”保存项目颜色变量、语义别名、字号、间距、按钮、表单、状态标签、任务行、证据条、上下文区域及确认弹窗。先检索团队与社区库，复用 Simple Design System 的按钮与输入框，再建立 HR 业务组件。中文使用 Noto Sans SC；本地 Demo 使用系统微软雅黑与 Segoe UI，不依赖在线字体。

“02 页面与流程”包含六个桌面主页面：人才工作台、招聘审阅、入职、员工服务、岗位培养、知识库。另有录用确认、请假预览及提交结果、主管审批、演练失败、复练、复练通过状态，以及 1024px 平板工作台、390px 员工服务与培训画面，共 16 个顶层画框。

从桌面工作台进入 Present：查看原文证据 → 确认录用 → 确认入职 → 请假预览及提交 → 主管审批 → 培训遗漏反馈 → 复练通过。设置了 104 个点击连接。原型用于展示操作关系；实际数据变化在 [本地 Demo](http://127.0.0.1:3220) 中执行。

手机稿可编辑，当前点击进入对应的桌面分步状态。完整手机业务可在 Demo 中操作。文件创建、原生图层与目视检查完成后，Figma Starter 工具配额耗尽，未追加独立的手机分步画框。没有将未执行的追加操作计入交付。

## 可编辑性与校验

页面包含 552 个原生文字节点、53 个组件实例；主体布局使用 Auto Layout，颜色绑定变量，截图只用于目视检查。主字号 14px，辅助字号 12px。程序检查 16 个画框的文字与父容器边界，未发现越界；桌面、平板和两张手机画面均已目视检查。

设计截图以 `figma-` 开头，保留设计检查时的状态；后续在原生文件中修正了员工与主管身份文案和导航范围。最终设计以原生文件为准，本地最新 UI 截图由 `test-results/e2e-report.json` 列出。

`figma-state.json` 与 `figma-screens.json` 记录原生节点、页面和流程入口；`scripts/figma/foundations.js`、`scripts/figma/screens.js` 是本次制作脚本，重新运行会新建图层，不能作为幂等更新命令。

## 数据保留与本地实现

业务 API、请求字段和 SQLite 表结构沿用原版。前端拆分至 `src/v2/`，入口为 `WorkbenchApp.tsx`，旧叠加样式与旧单文件页面已移除。按页面保存工作上下文和未提交草稿，知识库往返保持人员、任务、能力与引用；身份切换卸载原身份页面，慢响应不能覆盖新身份。

改版前在线备份位于 `data/backups/2026-10-30T14-12-46-913Z-before-ui-v2/`。改版后及启停验证后，业务 payload 与幂等记录哈希均与备份一致。原员工 1 人、培训 5 项及其他记录完整保留，未通过重置执行迁移。
