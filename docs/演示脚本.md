# People-Lab 演示脚本（当前版）

开场：“从一张生产订单出发，系统计算哪些能力工时没有覆盖，再把人工批准的路径落实为可追溯的培养任务或招聘需求草稿。”

主线按[评委快速上手](JUDGES-QUICKSTART.md)操作：准备虚构资料 → 10/8/2缺口 → 查看规则证据与风险 → HR批准 → 创建任务/草稿 → 查看真实记录 → 正式资格变化后重新计算10/10/0。推荐3–5分钟讲解，但尚未人工计时，不能当作实测完成时间。

讲解时主动区分：已分配容量与增量、已批准与已执行、培训通过与正式资格、历史快照与最新结果。不要强行演示不成立的调配成功。无需在主线中演示全局清库。

原HR全流程作为可选附线保留，按下方历史讲稿演示招聘→入职→年假→培训复练；时间分配为建议，非本轮测量。下面的全局重置提示仅适用于独立虚构库，不得用于日常库。

---

当前界面按钮：生产用工 → 前往人才方案 → 分析人才方案 → HR 审核 → 创建培训任务（或创建招聘需求草稿）→ 确认创建。正式资格变化后的0缺口页面不再引导重复计算。

# HRFlow 三分钟演示

演示前安装依赖并完成构建，确认一键启动成功。当前本机记录已保留，可以继续已有流程；需要从零演示时，由 HR 在界面确认重置。下面使用虚构质量检验员岗位与候选人陈雨桐。

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:35 | 工作台选一位候选人，查看右侧事项依据，进入招聘三栏审阅并切换能力 | 能力判断与简历原句同时可见。“待核实”只表示当前资料不足，由 HR 通过面试确认。 |
| 0:35–1:00 | HR 确认录用，完成入职清单并确认入职 | 候选人转成同一个关联员工档案，自动产生岗位培训任务，不需要重复录入。 |
| 1:00–1:40 | 切员工问请假制度、查看引用并返回；在同一办理卡内填写、预览和提交未来工作日下午半天假；切主管批准 | 制度依据始终保留。知识库往返保留草稿；批准后才从 3 天扣至 2.5 天。 |
| 1:40–2:25 | 切员工完成一次不完整演练，再开始复练并通过 | 同一岗位 SOP 用于培训和评估。反馈给出遗漏，复练完成后回写原任务。 |
| 2:25–3:00 | 切 HR 看驾驶舱、刷新页面 | 招聘、员工服务、培训共用持久化业务数据，管理者可以追踪进展和负责人。 |

开场可以说：

> 我们把招聘、员工服务和培训连接在同一条人才流程里。下面用一位新员工展示，招聘中的证据如何衔接入职后的服务与培养。

说明当前实现时可以说：

> 这是本地业务闭环原型。当前问答和评估采用固定规则与预置材料，审批、余额、任务和事件记录真实写入本地数据库。后续接入真实模型时，会沿用这些数据和流程约束。

现场可追加两个验证：刷新确认数据仍在；问一个资料没有覆盖的问题，展示转交 HR 人工工单。避免将本地演示规则描述成已经完成的大模型 RAG，也不要宣称未经测量的效率提升比例。
