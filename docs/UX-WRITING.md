# People-Lab 企业 HR 文案规范

研究日期：2026-10-31（Asia/Shanghai）。审计基线：`55d03a56140a9518a24d53435c05f001f07a7d64`。阶段 B 正式规范基于 main e98a501 实施。阶段 A 的23项来源与125项建议保留在配套研究档案；实际采用及验证见 PRODUCT-COPY-DELIVERY.md。

配套：[调研与审计](PRODUCT-COPY-AUDIT.md) · [逐页替换及冲突清单](PRODUCT-COPY-MAPPING.md)。来源编号见调研报告；中文建议均由 People-Lab 制定，除明确摘录外不冒充竞品原词。

## 1. 基本规则

面向 HR、生产主管和员工，先说明对象和动作，再提供必要依据。采用简洁、自然、专业的业务语言。

- 导航用业务名；标题补足对象；不在每页重复产品名、开发阶段和实现说明。
- 按钮用动词加对象。使用“确认录用”“提交申请”“批准方案”“创建培训任务”等；取消只关闭当前操作，返回只用于页面或步骤返回。
- 同一动作在桌面、手机、弹窗、提示、无障碍名称及指南中保持一致。aria-label 应包含可见名称，必要时增加对象以区分重复按钮。
- 成功提示只陈述已完成的事实。创建草稿不能称已发布；提交申请不能称已批准；审核通过不能称已执行。
- 首屏保留当前决定所需的说明。计算公式、版本和来源留在已有详情区域。若移动说明需要改变交互，另记为待评估，不混入纯文字修改。
- 不用“赋能”“智能驱动”“全链路闭环”修饰普通操作；不将规则匹配称为 AI 决策，不将待核验材料称为事实。
- 不压缩掉风险、权限、有效期、责任人及模型适用范围。身份切换始终标明“演示”，不改成“登录”。
- 不全局替换内部变量、字段、错误码或枚举；展示层按对象映射。服务端返回的历史文字也不能通过改规则重算来统一。

## 2. 导航及标题

当前实现有八个页面入口；“人才执行闭环”分布在 SkillBridge、招聘、培训和生产用工页面，不建议仅为凑齐九模块新增入口。

| 模块 | 导航建议 | 页面标题建议 | 说明 |
|---|---|---|---|
| 管理驾驶舱 | 管理驾驶舱 | 管理驾驶舱 | 保留既有业务概念，不把汇总指标称为全公司实时数据 |
| 招聘管理 | 招聘管理 | 招聘管理 | 页面内区分招聘需求、职位要求、候选人评审 |
| 入职管理 | 入职管理 | 入职管理 | 未完成入职的人员称“待入职人员” |
| 员工服务 | 员工服务 | 员工服务 | 年假申请、制度查询、HR咨询分别描述 |
| 培训管理 | 培训管理 | 培训管理 | 员工个人区域可用“我的培训”，不改模块权限 |
| 企业知识库 | 企业知识库 | 企业知识库 | 制度正文、版本、生效日期及引用保留 |
| Order2People | 生产用工 | 生产用工分析 | 品牌名可留为副标；输出工时缺口，不承诺排产或招聘人数 |
| SkillBridge | 人才方案 | 人才方案 · SkillBridge | 内部人才、资格差距、调配/培养/招聘方案；不扩大成全功能人才市场 |
| 人才执行闭环 | 不新增导航 | 方案执行（已有区域） | 批准与执行两步、分别留痕 |

以上为当前展示名称。员工身份使用“我的工作台”；页面标识及权限不变。

## 3. 企业 HR 统一术语表

| 术语 | 定义与建议使用场景 | 不得混同 | 依据 |
|---|---|---|---|
| 招聘需求 | 用人缺口形成的招聘申请/草稿，含岗位、技能及时间要求 | 招聘职位、候选人；本项目需求以缺口工时为依据，不能凭空补人数 | C1、I1；本项目契约 |
| 招聘职位 | 面向招聘流程描述的具体职位及任职要求 | 招聘需求、组织岗位；当前 Position 不等于新增需求 | C1、I1 |
| 候选人 | 正在招聘评审中的人员 | 已在职员工、招聘需求 | C1、I1 |
| 待入职人员 | 已录用但尚未完成入职办理的人员 | 在职员工；pending 不能一律译成“待审批” | I8；本项目 Employee |
| 在职员工 | 已完成入职且状态为 active 的员工 | 系统账号已激活或资格合格 | 本项目契约 |
| 员工技能 | 员工掌握的技能及相关记录 | 正式岗位资格、培训成绩 | I2、I10 |
| 岗位要求 | 岗位对技能、等级、资格等条件的要求集合 | 员工已经具备的能力 | I1、I2 |
| 岗位资格 | 经核验、满足资格类型/等级/来源/有效时段等任职条件 | 技能标签、证书附件、培训完成 | I2、I10；本项目 qualificationCovers |
| 资格证书 | 支持核验的证书材料；可有独立有效期 | 结业证明、全部岗位资格 | I2、I11 |
| 能力评价 | 对表现/熟练度的评价及其来源、日期、评价人 | 资格认证结论；规则演练评分只代表本次练习 | I10 |
| 培训任务 | 分配给员工的一项培训活动 | 课程目录、岗位资格；完成不升级资格 | I9 |
| 复练任务 | 本项目未通过演练后的再次练习任务 | 补考、资格复审；当前未实现相应正式制度 | 本项目自拟 |
| 需求工时 | 数量×单位人工工时＋批次×每批准备人工工时 | 机器节拍、订单历时、需求人数 | 自拟；Order2People公式 |
| 可用工时 | 指定人员与窗口的班次工时，扣除休假及既有占用（按并集去重） | 本次已分配工时、可新增分配工时 | 自拟；availableSeconds |
| 已分配工时 | 当前计算中分配给需求的人工工时 | 已预订产能、已执行调配；跨技能共享一份工时 | 自拟；allocations |
| 可新增分配工时 | SkillBridge 在当前窗口净可用工时基础上，再扣除原计算当日分配的剩余增量 | Order2People总可用工时；不可重复使用已分配8h补2h缺口 | 自拟；capacityFor |
| 能力缺口 | 指定工序/技能资格/窗口下未被合格人员覆盖的需求，当前以未覆盖工时量化 | 缺人数量、个人能力差距 | 自拟；GapLine |
| 未覆盖工时 | 需求工时减已分配工时，完整计算后才有确定值 | 数据缺失或阻断时的零值 | 自拟；gapSeconds |
| 资格差距 | 相对于指定岗位要求尚待满足或核实的资格条件 | 缺乏能力的断言、需求工时缺口 | I2、I10；本项目 |
| 审核 | 人工审阅方案及依据并作出批准/拒绝决定 | 确认输入、执行写入 | I5、I7；本项目 |
| 确认 | 对明确对象核对后确认，如确认输入、确认结果、主管确认 | 自动审批或执行；必须带对象 | 本项目 |
| 执行 | 对已批准方案创建培训任务、招聘需求草稿或调配工时占用 | 审核批准；不等于招聘完成/培训完成/员工已到岗 | 本项目 execute |
| 内部调配 | 当前项目将合格员工工时安排给目标订单并写入占用 | 正式调岗、内部应聘、晋升；不得套用竞品职位流动全套语义 | I6、I7用于区分；本项目 |
| 结果已过期 | 依赖的输入版本变化，该计算/分析不能继续作为执行依据 | 资格证书到期；历史记录仍可查看 | 本项目 stale |

逐条当前原词、代码位置、推荐词、语义和冲突标记见替换表，避免在此重复维护另一份替换数据库。

## 4. 按对象映射状态

| 对象及内部值（只读） | 展示建议 | 精确含义/注意 |
|---|---|---|
| 方案 draft | 待审核 | 当前生成即进入HR审核，没有独立提交审核动作；不能仅为术语对齐改成另一个状态 |
| 招聘需求 draft | 草稿 | 未开展招聘；与方案draft含义不同 |
| 招聘需求 open / closed | 招聘中 / 已关闭 | 不表示已发布到外部渠道；无撤回含义 |
| 方案 hr_approved / hr_rejected | 已批准 / 已拒绝 | 人工审核结果；保持拒绝，不暗示退回后可修改重提 |
| execution not_executed / executed | 未执行 / 已执行 | 执行标记独立于审核状态；附创建对象与记录入口 |
| execution blocked_stale | 需求已过期，无法执行 | 兼容枚举；409事务回滚，不能声称失败后已保存此状态 |
| 计算 blocked | 无法计算 | 显示缺失项及补充动作；缺口为未知，不是0 |
| 计算 calculated / confirmed | 待确认 / 已确认 | “已计算”可作详情事实；主状态用待确认说明下一步 |
| 计算 stale | 已过期 | 数据已变化；重新计算及HR确认后再用 |
| 分析 open / demand_stale | 当前有效 / 需求已过期 | open不表示计算仍在运行，分析结果创建时已生成；仅demand_stale时历史可查、不可继续审核或执行 |
| 员工 pending / active | 待入职 / 在职 | active在此不是“资格有效” |
| 入职 pending / completed | 待入职 / 已入职 | 本项目入职记录完成对应实际入职；逐项清单进度另行展示，不是请假状态 |
| 请假 pending / approved / rejected | 待审批 / 已批准 / 已拒绝 | 提交成功后待审批；批准时校验并扣余额 |
| 培训 not_started / learning / needs_retry / completed | 待学习 / 学习中 / 待复练 / 已完成 | 完成只指培训；不得显示“已取得资格” |
| 咨询 open / resolved | 待回复 / 已回复 | 当前业务是回复后关闭，不能据此称问题必然已解决 |
| 资格 unverified / verified / revoked | 待核验 / 已核验 / 已撤销 | verified本身不保证窗口、等级满足；详情仍展示有效期与要求 |
| 资格匹配 qualified_verified | 资格符合要求 | 不承诺有剩余工时、可直接调配；以完整匹配结果为前提 |
| potential_transferable / insufficient_evidence | 资格待补齐或核验 / 依据不足，待核实 | 当前规则包含低等级、未验证/过期资格或培训记录，并非证明跨技能迁移 |

“草稿→待审核→已批准→已执行→已过期”不是全局串行状态机；不同对象并行维护，已批准方案可以未执行，已执行记录仍需保留来源过期提示。

## 5. 按钮、提示与空状态

| 场景 | 推荐写法 | 采用条件 |
|---|---|---|
| 方案执行：培养 | 创建培训任务 / 确认创建 | 成功后显示“已创建培训任务”，不称培训完成 |
| 方案执行：招聘 | 创建招聘需求草稿 / 确认创建 | 不称发布职位或自动招聘 |
| 方案执行：调配 | 创建调配占用 / 确认创建 | 保留主管确认人、原岗位影响、资格和工时校验 |
| 原写入成功但刷新失败 | 操作已保存，页面暂未更新。请重试同步，勿重复提交。 | 仅在已知写入成功的路径用；若只知网络失败则不能声称已保存 |
| 无待处理缺口 | 当前无待处理缺口 | 已有完整且确认的计算时说明当前无缺口；没有有效确认结果时才引导计算和确认，阻断/过期结果不入列表 |
| 没有可见请假 | 当前没有可查看的请假申请。 | 体现个人/团队权限，不写全公司无人请假 |
| 资格或工时不足 | 资格或可新增分配工时不足，无法调配。请核查资格和任务占用。 | 同一错误码含多原因时不猜哪一种；保留不能重复补缺口 |
| 部分时段不支持 | 暂无法创建调配占用：当前模型不能核验部分时段承诺。请先补充实际调配区间和目标订单，并由维护人员核实支持范围。 | 若无可用补录入口，不写“补充后即可成功” |
| 输入版本冲突 | 数据已更新，请刷新后重新核对。 | 不自动重试旧的写入 |
| 服务失败且写入结果未知 | 暂时无法确认操作结果，请刷新并核对记录后再试。 | 不误报失败或重复创建 |

空状态通常包含“当前范围的事实＋下一步”，没有下一步时不强行放按钮。警告保留后果与责任，不堆实现细节。禁止用“系统错误”覆盖权限、版本冲突、条件不满足等可解释异常。

数字使用阿拉伯数字，工时显示“小时”或统一“h”，不混入“人”；有效时段保留时区与起止边界。未知显示“待补充/未确认/无法计算”，按原因选择，不把null格式化为0。格式化小数精度调整涉及展示逻辑，需单独审查，不属于词语替换。

实施后运行构建、单元/接口测试、相关浏览器测试；实际检查1440px桌面和390px移动端的按钮、状态、表格、弹窗、长错误与无障碍名称。不删断言、不降标准。同步用户指南、评委指南、演示脚本和必要导航，在AGENTS增加本规范入口。提交独立PR并等待审核，不自动合并。


## 7. 技术名称与历史记录

Order2People、SkillBridge 保留为页面品牌；SOP 首次说明为作业指导书；JSON 仅用于导出和高级维护；HR、工时单位 h、资格等级、版本与来源在需要核查的位置保留。已知演示目录显示业务名称，未知编号原样保留，不猜测。高级维护、原始来源和导出保留原 ID。服务端存储的历史说明不改写，只在前端映射已知表述。

计算引擎与方案引擎均不修改；前端中文状态不替代真实枚举。审核批准不等于执行，资格符合不等于有可新增分配工时，培训完成不授予资格。风险列表不得删减。
